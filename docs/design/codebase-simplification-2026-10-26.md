# 코드베이스 단순화 설계

이 문서는 기준 커밋 `52677e75d0ae796e08a5a6d89e97ded45584d5b3`의 코드베이스 단순화 검토와 설계 인터뷰를 기록한다. 2026-10-26에 Q1부터 Q5까지의 추천안을 수락하고 Q6에서 최종 범위·공개 테스트 경계·검토 기준을 확정한 뒤 `implement` 요청으로 구현을 승인했다. 다섯 개선안을 채택하고 문서 앵커 캐시는 보류한다. 아래 근거와 한계는 구현 전 검토 상태이며 구현·검증 결과와 구분한다.

## 근거와 한계

검토는 런타임 소스, 호출 관계, 관련 테스트와 저장소 문서에 근거한다. 테스트와 브라우저를 실행하지 않았으며 성능 개선량도 측정하지 않았다. 반복 작업의 존재와 삭제 가능한 경로는 정적 근거이고, 사용자 체감 성능이나 접근성 개선은 검증 결과가 아니다.

## 합의한 결정

### Q1: 같은 표시값의 본문 DOM 유지

[사이드 패널](../../extension/sidepanel.js)의 상태 폴링과 두 응답의 독립 처리는 유지한다. 상태·진행률·오류·컨트롤의 갱신도 유지한다. 본문 쓰기만 현재 DOM과 최종 표시값을 비교해 생략한다. 이전 표시값을 별도 캐시하지 않는다.

원문은 최종 본문과 언어를 비교한다. 단일 번역 본문은 본문 구조, 최종 텍스트와 언어를 비교한다. 이중 언어 본문은 부분별 순서·텍스트·언어와 부모의 언어를 비교한다. 합친 문자열만 같은 경우를 같은 DOM으로 취급하지 않는다. 보기 방식은 최종 구조에 반영하며 별도 캐시 키를 만들지 않는다.

원시 번역문이 아니라 안내 문구까지 포함한 최종 표시값을 사용한다. 같은 텍스트의 언어 변경, 단일·이중 언어 보기 전환, 빈 상태·추출 중·번역 중 상태의 안내 문구를 반영한다. 탭 전환 시 기존 초기화와 늦은 응답 차단은 유지한다. 텍스트는 HTML로 해석하지 않는다.

동일 본문 갱신에서 노드 교체가 사라지면 텍스트 선택을 유지하는 데 도움이 될 수 있지만 현재는 미검증이다. 후속 브라우저 검사에서 선택 유지와 기존 키보드·언어 범위를 확인한다.

### Q2: 확정된 선택과 한 번의 순회, 하네스의 연결 보장 활용

[본문 선택](../../extension/content.js)은 앞뒤 공백을 제거한 article의 본문이 400자를 넘을 때 먼저 반환한다. 내부 공백은 길이에 포함한다. 400자는 일반 후보 비교 대상이고 401자는 우선 반환 대상이다. 작은 article 또는 article이 없는 경우에는 기존 후보 순서와 최장 본문 비교, 동점 처리를 유지한다. Side Panel Translation에서 추출한 Markdown이 짧을 때 body로 재추출하는 별도 규칙도 유지한다.

[Semantic Block 직렬화](../../extension/inline-block.js)의 `rememberContainer()`에서는 누적 배열의 중복 검색만 삭제한다. 루트, 일반 wrapper와 자체 순회 후 반환하는 opaque subtree의 방문 경로는 현재 지원하는 동기 DOM 순회에서 겹치지 않는다. 별도 Set을 추가하지 않고 컨테이너 등록 순서·자식 스냅샷·복원 순서를 유지한다. 적용과 복원의 소유권 검사는 변경하지 않는다.

[disclosure 검사](../../tests/integration/ai-hero-disclosure.smoke.test.mjs)와 [grill-with-docs 검사](../../tests/integration/ai-hero-grill-with-docs.test.mjs)는 [공용 하네스](../../tests/integration/harness.mjs)가 반환한 `page`를 직접 사용한다. 두 파일 내부의 `attachReportedPage()`와 도달하지 않는 재탐색 경로를 삭제한다. 하네스가 페이지 연결에 실패하면 기존 예외 경로로 종료하며 검사 출력용 확인은 유지한다. 하네스가 반환한 뒤의 연결 유지나 재연결을 새로 보장하지 않는다.

이 검사들을 실행할 때 정리는 각 검사가 연 이름 있는 브라우저 세션으로 제한한다. disclosure 검사의 기존 전체 브라우저 종료는 해당 세션 종료로 좁혀 다른 작업의 세션을 보존한다.

### Q3: 정규화한 고유 ID 입력에서 원본 레코드 재검색 제거

[모델 실행기](../../extension/inline-model-execution.js)의 초기 검증 결과는 입력 레코드 순서로 생성된다. 수리 대상의 원본은 같은 인덱스로 가져오며 반복 `find()`를 제거한다. 역순 모델 응답의 정렬, 선별 수리, 최초 성공 결과, 수리 요청 순서와 실패 진단은 유지한다.

동작 보존 범위는 운영 호출자인 [worker](../../extension/background.js)가 정규화한 고유 ID 입력이다. 중복 ID를 서로 다른 원본에 부여해 실행기를 직접 호출하면 기존 `find()`와 인덱스 접근은 다른 원본을 선택할 수 있다. 모든 직접 호출 입력에 대해 동일하다고 주장하지 않는다. 중복 ID는 기존 worker 경계에서 거절하며 실행기에 별도 검증이나 호환 처리를 추가하지 않는다.

### Q4: 문서 앵커 캐시 보류

[문서 검사기](../../scripts/check-docs.js)는 같은 대상의 앵커마다 Markdown을 읽고 제목을 다시 파싱한다. 반복 작업은 있지만 실행 시간의 병목은 측정되지 않았다. 캐시는 상태 관리를 추가하고 검사 도중 파일 내용이나 저장소 내부 심볼릭 링크 대상이 바뀌었을 때 기존과 다른 결과를 낼 수 있다. 이번 작업에서는 변경하지 않는다. 실제 병목이 측정되면 캐시 수명과 검사 중 변경의 처리 계약을 함께 재검토한다.

### Q5: 문서화 경계

채택·보류 이유와 검증 경계는 이 설계 기록과 [문서 색인](../README.md)에 남긴다. 새 도메인 개념은 없으므로 용어집을 변경하지 않는다. 국소적이고 되돌리기 쉬운 정리이므로 ADR을 추가하지 않는다. 현재 구현 관계를 바꾸지 않는 설명을 아키텍처 문서에 중복해서 추가하지 않는다.

## 확정한 범위와 검증 기준

| 저장소 | 작업 범위 | 공개 테스트 경계 | 검토 기준 |
| --- | --- | --- | --- |
| chrome-ai-translator | 사이드 패널 본문 쓰기 생략, article 조기 선택, 컨테이너 중복 검색 삭제, 초기 수리 대상 인덱스 접근, 두 브라우저 검사의 페이지 재탐색 삭제, 필요한 기존 테스트·fixture 보완, 이 설계 문서와 색인 | 실제 패널 DOM과 상태 메시지, 콘텐츠 메시지 진입점, 직렬화·적용·복원 API, 모델 요청 어댑터와 반환값, 브라우저 하네스의 반환·실패 및 전용 검사 출력·종료 코드 | `52677e75d0ae796e08a5a6d89e97ded45584d5b3` 대비 설계 기록과 후속 구현을 포함한 작업 트리 |

후속 구현의 검증은 다음과 같다.

- 패널: 동일 상태 재조회에서 본문 쓰기·노드 교체가 없고, 같은 본문의 언어 변경·양방향 보기 전환·안내 문구 변경·탭 전환을 반영한다. 현재 DOM이 달라진 경우 같은 상태 조회로 올바른 결과를 복구한다. 두 상태 응답의 독립 처리와 늦은 응답 차단을 유지한다. [기존 패널 단위 검사](../../tests/sidepanel-tab-state.test.js)와 [비과금 UI 검사](../../tests/integration/ui-polish.test.mjs)를 사용한다.
- 본문 선택: 서로 다른 article·main·body와 400/401자, 주변 공백, article 부재, 동점, 여러 선택자가 같은 요소를 가리키는 경우를 콘텐츠 메시지 경계에서 확인한다. [콘텐츠 하네스](../../tests/content-harness.js)는 현재 선택자를 모두 body로 반환하므로 필요한 선택자 구분만 보완한다. 기존 추출 fallback도 확인한다.
- 컨테이너: [codec 검사](../../tests/inline-block.test.js)의 wrapper·atom·heading control·Block Child를 포함한 노드 동일성과 정확한 복원, 소유권 변경 거절을 확인한다.
- 모델 실행: [실행기 검사](../../tests/inline-model-execution.test.js)의 역순 응답, 선별 수리, 프로토콜 실패와 수리 실패를 확인한다. 중복 ID 거절은 [worker 검사](../../tests/background-helpers.test.js)의 기존 입력 경계에서 확인한다.
- 페이지 연결: [하네스 검사](../../tests/integration-harness.test.js)의 시작 실패와 사용 가능한 page 반환을 확인하고, 변경한 두 전용 브라우저 검사에서 기존 출력·종료 동작을 확인한다. 페이지 재탐색 삭제 자체를 문구나 함수 부재로 검사하지 않는다.

필요한 검사 추가와 읽기 전용 검토를 마친 뒤 소스를 고정하고 `npm test`, `npm run check:syntax`, `npm run check:docs`와 영향을 받는 비과금 브라우저 검사를 실행한다. 브라우저 검사는 `test:integration:ui`, `test:integration:ai-hero-disclosure`, `test:integration:ai-hero-grill-with-docs`이다. 각 실행 전에 현재 정의·선행 조건·네트워크 범위를 확인한다. 새 검사로 반복 작업 감소나 경계 보존을 입증한다면 해당 동작을 되돌린 대조군이 같은 검사에서 실패하는지도 확인한다. 시간 임계값으로 성능을 단정하는 검사는 추가하지 않는다.

이 검증에는 실제 모델 요청이나 자격 증명 접근이 필요하지 않다. 브라우저 검사 중 공개 페이지 접근과 로컬 결정적 적용은 실제 모델 품질 검증과 구분한다. 실행하지 못한 검사는 이유와 함께 별도로 보고한다. 커밋·푸시·배포는 이 설계 확인의 범위가 아니다.
