# mise 형제 컨테이너 설계 인터뷰

이 문서는 [이슈 #110](https://github.com/mochafreddo/chrome-ai-translator/issues/110)의 남은 공개 페이지 조건을 위한 2026-11-01 설계 인터뷰를 기록한다. 조사 기준은 `ed567c0686b50dcd20d2addd0596daf8daee277a`이다. 사용자는 Q1부터 Q5까지의 추천안을 수락해 설계를 확정했다. 구현과 원격 변경은 승인 범위에 포함하지 않는다.

## 관측과 기존 계약

이슈 본문은 단일 DIV 래퍼 지원이 구현됐으나 공개 mise 페이지의 네 목록 항목이 형제 DIV 구조여서 거부됐다고 기록한다. [ADR-0012](../adr/0012-translate-through-a-sole-generic-div-wrapper.md)는 유일한 DIV 래퍼만 허용하고 형제 요소를 거부한다. [ADR-0011](../adr/0011-exclude-block-children-from-own-prose.md)은 가장자리 Block Child의 객체와 위치를 보존하면서 부모와 자식의 번역·복원을 독립적으로 유지하는 근거다.

2026-11-01 별도 임시 브라우저 세션에서 `https://mise.jdx.dev/`의 네 `li.recipe-row`를 읽었다. 각 LI에는 `recipe-text`와 `recipe-code terminal-lines` 클래스의 DIV가 형제로 있다. 앞 DIV에는 `Step N` 표시, H3, P가 있고 뒤 DIV에는 DIV·SPAN으로 구성한 명령문과 출력값이 있다. 뒤 DIV를 감싸는 PRE 또는 CODE는 없다. 일부 출력은 `v24.x.x`나 `development`와 같은 평문이다. 클래스 이름이나 화면 배치만으로 일반 DIV의 내용을 코드라고 확정하는 범용 규칙은 아직 합의하지 않았다.

이 관측은 현재 DOM 구조에 한정한다. 이번 조회에서는 codec 검사, 번역 적용·복원 또는 실제 모델 품질을 검증하지 않았다.

## 합의한 방향

### Q1: 실제 형제 컨테이너 구조 지원

사용자는 추천안을 수락했다. 지원 목표를 실제 형제 컨테이너 구조에서도 단계 표시를 번역하는 것으로 넓힌다. 제목·문단의 독립 번역과 코드·DOM 보존을 성공 조건으로 삼는다. 이는 ADR-0012의 형제 요소 거부 제한을 재검토하는 선택이다.

### Q2: 사이트와 구조에 한정한 지원

사용자는 추천안을 수락했다. `mise.jdx.dev`의 확인된 목록 구조에서만 설명 컨테이너를 번역하고 코드 컨테이너를 보존한다. 클래스 이름을 범용 코드 판별 규칙으로 사용하지 않으며, 일반 DIV 전체를 Block Child로 취급하지 않는다. 별도 플러그인 체계 없이 기존 직렬화와 소유권 검사를 활용하는 방향이다. 사이트 마크업에 의존한다는 한계를 수락했다. 결정의 근거는 [ADR-0013](../adr/0013-recognize-mise-recipe-layout-explicitly.md)에 기록한다.

### Q3: 확인된 구조의 허용 경계

사용자는 추천안을 수락했다. mise 홈페이지의 `LI.recipe-row`에 `DIV.recipe-text`와 `DIV.recipe-code.terminal-lines`가 그 순서로 있고 바깥에는 공백만 있는 경우를 허용한다. 설명 DIV에는 기존 단일 래퍼의 속성 제한을 유지한다. 코드 DIV 내부는 관측한 DIV·SPAN·텍스트 구조로 제한하며 링크·버튼·입력 요소나 편집 가능한 내용이 추가되면 거부한다. 다른 사이트나 구조는 기존 판정을 유지한다.

### Q4: 코드 내용 갱신과 독립 소유권

사용자는 추천안을 수락했다. 같은 코드 컨테이너 안에서 명령문·출력 텍스트가 바뀌어도 페이지의 최신 내용을 그대로 보존하면서 단계 표시를 번역·복원할 수 있다. 코드 컨테이너의 교체·이동이나 허용 경계의 변경은 적용·복원 전에 다시 검사한다. 단계 표시와 제목·문단은 각자의 소유권에 따라 독립적으로 번역·복원한다. 코드 하위 트리를 과거 스냅샷으로 되돌리지 않는다.

## Q5: 확정한 설계와 검증 범위

사용자는 다음 작업 범위, 공개 테스트 접점, 검토 기준과 검증 범위를 최종 수락했다. 기존 Semantic Block과 Block Child 용어를 사용하며 새 도메인 용어는 추가하지 않는다.

- 저장소는 `/Users/mochafreddo/GitHub/chrome-ai-translator`이며 검토 기준은 `ed567c0686b50dcd20d2addd0596daf8daee277a`이다. 설계 문서와 ADR을 포함해 이 기준 이후의 작업 변경을 검토한다.
- 작업 범위는 Q1–Q4의 codec 경계와 소유권, 필요한 경우 해당 경계를 발견하는 Viewport 경로, 회귀 검사와 현재 동작 문서 갱신이다. `https://mise.jdx.dev/` 홈페이지의 확인된 구조에 한정하며 일반 DIV 지원은 넓히지 않는다. 기존 문서·용어집의 다른 계약은 유지한다.
- codec의 공개 `serializeBlock`, `validateTranslatedTemplate`, `applyTranslatedTemplate`, `restoreBlock`과 Viewport의 `createInlineViewport`를 통해 검사한다. 공개 codec 호출에 새 사이트 설정 인자를 추가하지 않고 실제 요소의 문서 위치를 경계의 근거로 사용한다.
- 기존 단위 검사에서 올바른 사이트와 구조의 수락, 다른 사이트·경로·형제 순서·요소·금지 속성과 상호작용·편집 가능 내용의 거부를 확인한다. 부모·제목·문단의 적용·복원 순서 독립성, 코드 텍스트 갱신 보존, 컨테이너 교체·이동 및 경계 변경 시 페이지를 덮어쓰지 않는 결과를 확인한다. Viewport를 통한 단계 표시의 LI 발견과 admission도 검사한다.
- 회귀 검사는 미수정 코드에서 실패하는 음성 대조를 포함한다. 최종 로컬 검증은 `npm run verify:local`을 사용한다. 실제 브라우저에서는 사이트 위치 판정까지 재현하는 고정 fixture와 고정 번역 응답으로 단계 표시 적용, 노드·코드 보존 및 복원을 검사한다. fixture와 공개 페이지 관측은 구분한다.
- 이슈의 공개 페이지 조건은 `npm run --silent inspect:inline-blocks -- --url https://mise.jdx.dev/ --root body`로 다시 관측한다. 현재 페이지의 네 recipe-row LI 수락 여부를 기록하며 이를 영구적인 개수 단언으로 만들지 않는다. 실제 모델 품질 검증은 포함하지 않는다.
- 최종 설계 확인은 공동 이해에 대한 확인이다. 제품 구현, 유료 모델 호출, 자격 증명 접근, 커밋·푸시·병합과 GitHub 변경은 별도 요청 전에는 수행하지 않는다.

## 후속 구현 요청

사용자는 설계 확정 후 `implement`를 요청해 합의한 범위의 구현과 로컬 커밋을 승인했다. 원격을 새로 조회한 시점의 `origin/main`과 로컬 HEAD는 모두 조사 기준인 `ed567c0686b50dcd20d2addd0596daf8daee277a`였다. 저장소의 이슈 브랜치 규칙에 따라 `issue-110-mise-sibling-containers`에서 구현한다. 설계·ADR·색인의 기존 변경도 이번 작업에 포함한다. 푸시·병합·GitHub 변경과 유료 모델 호출은 요청에 포함하지 않는다.

## 구현과 공개 페이지 관측

구현은 기존 codec의 prose 컨테이너·소유권 경로에 mise 경계를 추가한다. 실제 문서의 위치로 사이트를 판정하며 base URL로 다른 사이트를 허용하지 않는다. 코드 컨테이너의 하위 트리는 요청과 부모 텍스트 스냅샷에서 제외하되, 컨테이너 정체성과 순서 및 허용 조건은 적용·복원 때 재검사한다. Viewport의 기존 발견 경로를 유지하고 공개 접점을 통한 admission 회귀 검사를 추가했다.

2026-11-01 무료 공개 페이지 검사에서 전체 후보 64개 중 기존 recipe-row 위치인 47·50·53·56번 LI가 모두 수락됐다. 이 숫자는 검사 당시 관측이며 영구적인 개수 단언이나 실제 모델 품질 측정이 아니다. 검사 도구의 첫 브라우저 시작은 실패했고, 작업 전용 소켓 경로와 namespace를 줄인 재시도는 성공했다. 소켓 길이 제약은 재시도 근거이며 최초 실패의 직접 진단은 브라우저 시작 실패까지만 제공됐다.

고정 브라우저 fixture는 실제 mise 홈페이지 URL의 탐색을 로컬 HTML 응답으로 가로채 사이트 판정과 DOM 동작을 검사한다. 같은 마크업의 loopback 주소에서는 거부하고, mise 주소에서는 부모·제목·문단 발견과 독립적인 적용·복원, 최신 코드 출력 보존, 코드 컨테이너 교체 거부를 확인했다. 공개 페이지 관측과 구분되며 실제 모델을 호출하지 않는다. 실행 명령과 범위는 [테스트 가이드](../../tests/README.md#unbilled-chrome-checks)에 있다.
