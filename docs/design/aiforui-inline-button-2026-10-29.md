# 본문 내 버튼 보존 설계 인터뷰

이 문서는 2026-10-29의 aiforui.dev Inline Translation 오류 조사와 설계 인터뷰를 기록한다. 조사 기준은 `15abb5e83ff1d1567392f5b4aa31b3eb98f0e2f3`이다. 사용자는 Q1부터 Q5까지의 추천안을 수락하고 최종 확인안 제시 후 `implement` 스킬로 해당 범위의 구현을 요청했다.

## 관측과 한계

사용자가 제공한 진단의 2026-10-29 실패는 `local_preflight` 단계의 `runtime.unsupported_block`이다. `localRejection`은 `interactive_content`, `BUTTON`이며 해당 실패 기록의 `modelRequestAttempts`는 0이다. 조사 기준의 codec은 Semantic Block 안의 버튼을 거부한다. 관련 책임과 기존 계약은 [architecture](../architecture.md#dom-boundaries), [ADR-0002](../adr/0002-translate-semantic-blocks-not-text-nodes.md), [ADR-0009](../adr/0009-model-local-rejections-in-diagnostics-v3.md)에 있다.

초기 조사에서는 독립된 agent-browser 세션으로 공개 페이지를 읽었다. 의미 블록 태그 안의 버튼을 좁혀 조회한 결과, 문단 안의 `Lapse` 버튼 하나가 확인됐다. 앞뒤에 문장이 있고 버튼은 `type="button"`, `aria-haspopup="dialog"`, `aria-expanded="false"`를 가진다. 내부에는 문구를 감싼 SPAN이 있다. 이 구조는 첨부 진단의 거부 조건과 일치하지만 진단에는 위치 정보가 없어 과거 실패 대상을 확정하지는 못한다. 초기 조사에는 버튼 클릭, 번역 적용, 원문 복원 검증이 포함되지 않았다. 후속 구현의 실행 절차와 검증 범위는 [테스트 가이드](../../tests/README.md#unbilled-chrome-checks)에 있다.

## 합의한 방향

### Q1: 버튼을 보존하면서 주변 본문 번역

사용자는 추천안을 수락했다. 버튼을 포함한 Semantic Block의 주변 본문을 번역하는 것이 목표다. 버튼 자체, 버튼 문구와 클릭 동작은 보존한다. 안전하게 보존할 수 없는 구조는 계속 거부한다.

### Q2: 번역 어순에 따른 이동

사용자는 추천안을 수락했다. 버튼 문구와 DOM 객체를 그대로 보존하면서 버튼 위치는 번역 어순에 따라 문장 안에서 이동할 수 있다. 모델에는 버튼 대신 Placeholder Token을 보내고 기존 버튼을 결과 위치에 배치한다. 문장을 조각내 번역하는 경로는 추가하지 않는다.

### Q3: 지원 범위

사용자는 추천안을 수락했다. 초기 지원 범위는 명시적인 `type="button"` 버튼과 단순한 내부 문구·강조 요소다. 폼 제출·초기화 버튼, 입력·편집 요소가 들어간 버튼, `role="button"`으로 만든 사용자 정의 컨트롤은 계속 거부한다. 사이트 주소에 따른 예외는 두지 않는다.

### Q4: 페이지 변경과 복원 경계

사용자는 추천안을 수락했다. 버튼 문구·내부 구조·위치가 바뀌면 번역 적용이나 원문 복원을 중단한다. 열림 상태·비활성 상태 같은 속성 변경은 페이지의 최신 상태를 보존한다. `type` 변경처럼 지원 조건을 벗어난 경우에도 적용·복원을 중단한다. 오래된 번역이나 원문으로 페이지 변경을 덮어쓰지 않는다.

### Q5: 포커스와 페이지 상태 보존

사용자는 추천안을 수락했다. 번역 적용과 원문 복원 모두에서 버튼의 DOM 객체, 문구, 클릭 동작, 현재 포커스와 페이지 상태를 보존한다. 버튼에 포커스가 있는 상태의 어순 변경과 복원을 실제 브라우저에서 클릭 동작과 함께 검증한다. 기존 일반 atom의 재배치가 이 조건을 충족한다는 실행 근거는 아직 없다.

## 구현 범위

사용자가 `implement` 스킬로 다음 범위의 구현을 요청했다.

- 작업 범위는 Inline Translation의 본문 내 버튼 지원, 관련 단위 검사·무료 브라우저 검사, 현재 동작 문서다. Q1부터 Q5의 보존·거부 계약을 적용하며 사이트 주소별 예외나 텍스트 조각 번역은 추가하지 않는다. 단순 자식 구조는 텍스트, 주석, 비상호작용 SPAN과 기존 강조 wrapper로 제한하며 숨김·편집·중첩 상호작용 구조는 거부한다.
- 기존 토큰 계약을 사용한다. 버튼 문구는 보호된 문맥으로 전달하고 주변 본문만 번역 품질 검사 대상으로 삼는다. 토큰 누락·중복·잘못된 중첩은 거부한다. 캐시를 재사용하더라도 현재 버튼의 객체·문구·지원 조건·소유권을 확인한다.
- 공개 단위 검사 접점은 codec의 `serializeBlock`, `validateTranslatedTemplate`, `applyTranslatedTemplate`, `restoreBlock`과 Session의 admission, batch, settlement, cache, progress다. 지원·거부 입력, 어순 변경, 노드 정체성, 버튼 문구의 품질 검사 제외, 캐시 격리와 재사용, 페이지 변경 시 적용·복원 거부를 검사한다.
- 무료 브라우저 검사는 로컬 재현 fixture와 공개 aiforui.dev 문단을 사용한다. 결정적 번역 결과로 어순을 바꿔 실제 클릭·키보드 포커스·상태 보존·정확한 원문 복원을 검사한다. 페이지가 바뀐 경우 원문 복원보다 최신 페이지 변경 보존을 우선한다. 실제 모델 호출은 하지 않는다.
- 구현 검증은 `npm test`, `npm run check:syntax`, 관련 문서 검사와 전용 무료 브라우저 검사로 구성한다. 회귀 검사는 미수정 코드에서 실패하는 음성 대조를 포함한다. 유료 모델 검사, 배포와 Git 원격 게시를 포함하지 않는다.
- 저장소는 `/Users/jw.kim/workspaces/chrome-ai-translator`이며 검토 기준은 `15abb5e83ff1d1567392f5b4aa31b3eb98f0e2f3`이다. 이후 기준 변경이 필요하면 관련 동시 변경을 확인하고 기록한다.

새 도메인 용어는 아직 확정하지 않았다. 기존 Inert Page Node는 동작 의미가 없는 요소이므로 버튼을 그 용어에 포함하지 않는다.
