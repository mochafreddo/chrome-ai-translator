# 코드베이스 전체 검토 후속 설계

2026-11-27 전체 코드베이스 검토에서 나온 14건에 대해 Q1–Q8의 추천안을 채택했다. 검토 기준은 `0ff80c628bc0f25c7899713dd09f864c990f4d37`이다. 설계 라운드 전에 GitHub `main`과 로컬 `HEAD`가 이 커밋과 일치함을 확인했다. 이 기록은 구현 전 설계 합의를 남긴다.

## 합의한 동작

- **Q1. Inline 콘텐츠 적격성 (I-02, I-04).** 최초 탐색의 조상 제외 규칙을 페이지 변경 재시도 직렬화와 캐시 적용 전에 다시 사용한다. 콘텐츠 스크립트가 배치를 워커에 보내기 직전에도 현재 DOM에 같은 제외 규칙을 적용한다. 적격 판정 후 화면 밖으로 스크롤된 블록은 처리할 수 있다. 선택된 기사 루트가 분리됐을 때 명시적인 재탐색을 요구하는 계약을 유지한다. SVG 하위 트리는 탐색 초기에 건너뛴다. [문서와 기사 루트의 수명](../adr/0014-bind-translation-to-the-readers-document-and-provider.md)과 [페이지 변경 재시도](../architecture.md#cache-and-page-changes)를 따른다.
- **Q2. Inline Translation Operation 종료 (I-01).** 사이드 패널과 Floating Translate Button의 Stop 및 Original text는 같은 종료 경로를 사용한다. 콘텐츠 스크립트가 종료를 알리면 워커는 이를 수락한 뒤 해당 탭·문서·Operation의 모든 새 초기 요청과 보정 요청을 실제 전송 직전에 막는다. 새 Operation과 이미 전송된 요청의 정산은 각자의 수명을 따른다. 전송 전에 차단된 보정은 전송 횟수와 Session Budget의 보정 비용에 포함하지 않는다. [늦게 도착한 보정의 정산](../adr/0007-charge-the-session-budget-in-actual-record-cost.md#consequences)을 유지한다.
- **Q3. 패널 정기 조회와 오류 안내 (UI-02, I-03).** 같은 문서의 Inline 상태와 워커 호출 오류는 독립적으로 조회한다. 한쪽의 정기 조회가 진행 중이면 그쪽의 다음 정기 조회를 건너뛴다. 문서 전환과 명시적 조작에 따른 갱신은 즉시 처리하며, 이전 문서의 답변은 현재 패널에 반영하지 않는다. Inline의 OpenAI 오류는 워커가 분류한 코드에 대응하는 고정 안내로 표시한다.
- **Q4. Options 키 입력 (UI-01).** 저장을 요청한 시점의 서비스와 입력값을 캡처하고, 변경이 필요한 Chrome 권한 요청은 그 사용자 조작에서 시작한다. 워커가 저장을 확인한 뒤 해당 서비스와 입력 편집이 그대로일 때 키 입력란을 비운다. 실패한 제출과 응답을 기다리는 동안의 새 편집은 보존한다.
- **Q5. Text Translation 완료·삭제·보관 (UI-04, UI-05, UI-06).** 마지막 분량의 결과를 받으면 완료로 표시하고 보관 오류는 별도로 안내한다. 이전 저장본도 유효한 결과가 모든 분량에 있으면 완료로 복원한다. Clear에 실패하면 이전 초안이 남아 있으며 Clear를 다시 시도할 수 있다고 안내한다. 길이 제한을 벗어난 설정의 필드에 오류를 표시하면서, 원문은 마지막 유효한 설정이나 기본값과 함께 기존 탭별 저장 경로에 보관한다. 번역 실행과 재개에는 그 작업의 실제 설정을 사용한다. [완료와 중단의 기준](../adr/0015-preserve-completed-text-translation-on-interruption.md)을 따른다.
- **Q6. 유료 검사 세션과 키 정리 (TOOL-01, TOOL-06).** 실행마다 고유한 브라우저 세션 이름을 부여하고 해당 실행의 세션만 정리한다. OpenAI는 현재와 이전 키 저장 위치를, OpenRouter는 선택한 서비스의 키 저장 위치를 브라우저 안에서 확인한다. 정리 결과는 키의 부재 여부만 브라우저 밖으로 전달한다.
- **Q7. 페이지 검사와 모델 평가의 출력 (TOOL-04, TOOL-05).** 공개 페이지 검사는 준비 확인부터 측정까지 격리된 JavaScript 환경을 사용한다. Node는 허용한 메타데이터 값만 출력하며 오류에 페이지가 제공한 원시 문자열을 그대로 싣지 않는다. 모델 품질 평가는 모의·유료 두 진입점에서 첫 출력 디렉터리 생성 전에 실제 상위 경로를 확인하고 저장소 안의 경로를 거부한다. 평가 자료의 취급 범위는 [테스트 안내](../../tests/README.md#model-quality-corpus-preparation)에 따른다.
- **Q8. 브라우저 CI의 의존성 (TOOL-02).** 브라우저 드라이버와 전이 의존성을 저장소의 npm 잠금 파일에 등록하고 CI에서는 그 파일로 설치된 실행 파일을 사용한다. 별도로 내려받는 브라우저 런타임에는 발행자의 체크섬 또는 서명을 확보할 수 있는지 구현 단계에서 확인한다. 이 기록 시점에는 해당 자료의 제공 여부를 확인하지 않았다.

Q1–Q8은 작성자와 다른 Codex `reviewer` 모델 `gpt-6.2-astra`로 독립 검토했다. 기존 [용어집](../../GLOSSARY.md)의 Inline Translation Operation, Inline Translation Session, Session Budget, Text Translation을 사용한다.

## Q1 후속 합의: 미전송 Semantic Block의 재등록

#125의 통합 후보 `ca7e5c4`에서 대기 중인 문단이 잠시 분리된 사이 전송 슬롯이 비면, 같은 요소를 다시 삽입해도 같은 Inline Translation Operation에서 전송되지 않는 현상을 재현했다. Viewport는 재탐색을 예약하고 Session이 미전송 레코드를 관리한다. 탐색에서 변경된 원문을 다시 발견하면 전송 슬롯이 가득 차 있어도 미전송 최초 레코드를 갱신한다. Session은 배치를 만들기 직전에 현재 적격성과 원문 스냅샷을 확인한다. 이 확인에서 탈락한 미전송 최초 레코드는 이후 적격인 Semantic Block을 다시 발견하면 등록할 수 있다.

원문이 그대로인 문단은 스크롤로 화면 밖에 나가도 처리할 수 있다. 수정된 원문이 화면 밖에 있으면 정상 탐색에서 다시 발견될 때 등록한다. 이미 전송한 레코드의 재시도와 Session Budget 정산은 기존 계약을 따른다. 선택된 기사 루트가 분리되면 독자가 **Scan visible text**를 실행할 때까지 자동 제출을 멈춘다. [기사 루트의 수명](../adr/0014-bind-translation-to-the-readers-document-and-provider.md)과 [정산 기준](../adr/0007-charge-the-session-budget-in-actual-record-cost.md)을 따른다.

속성 변경으로 앞 문단이 새로 드러날 때에는 다음 배치에서 이미 대기하던 뒤 문단보다 먼저 처리한다. 네 번째 검토 기준은 `ca7e5c43968b4d7f3ac13e1d21c1c5b9e103f7de`다. 합성 Operation 및 Viewport 검사에서 재삽입, 슬롯 반환 전 원문 변경, 기존 배치 순서, 화면 밖 대기 보존과 기사 루트 분리를 확인한다. 최종 로컬 검증과 무과금 Chrome의 DOM 변경 및 캐시 적용 검사도 실행한다.

## 확정한 구현 및 검증 범위

- **Q9. 작업 범위와 리뷰 기준.** 14건을 전용 worktree 하나에서 Inline·사이드 패널, Text Translation·Options, 검사 도구·CI의 세 묶음으로 진행한다. 리뷰 기준은 `0ff80c628bc0f25c7899713dd09f864c990f4d37`이며, 구현 착수 전에 `origin/main`을 다시 확인한다.
- **공개 검증 접점.** 콘텐츠 스크립트의 조작에서 워커의 합성 응답 처리까지 이어지는 경로, 사이드 패널 컨트롤러, Options 저장, Text Translation의 보관과 복원, 검사·평가 CLI, 모의 키 정리를 사용한다. 동시 검사가 각자 자기 세션만 닫는지와 OpenAI의 이전 키 삭제만 실패한 경우에도 정리 실패가 전달되는지 확인한다.
- **실행 검증.** 묶음별 회귀 검사와 최종 `npm run verify:local`을 실행한다. 무과금 Chrome 픽스처에서 변경된 메시지 전달과 격리된 CDP 검사를 확인한다. 브라우저 CI 설치 변경은 기존 전역 드라이버에 의존하지 않는 깨끗한 환경에서 잠금 파일로 설치한 드라이버를 사용해 확인한다. 실제 키를 쓰는 검사와 유료 공급자 호출은 별도 검증 범위다. [저장소 테스트 안내](../../tests/README.md)를 따른다.

Q9의 작업 및 검증 범위는 동일한 Codex `reviewer` 모델로 독립 검토했다. 구현과 GitHub 게시는 별도 요청으로 진행한다.
