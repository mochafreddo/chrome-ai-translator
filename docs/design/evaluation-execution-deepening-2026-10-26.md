# 비교 실행 module 설계

이 문서는 기준 커밋 `5845180e971ad97b9a91cfe544c350e6e5aa47a8`의 아키텍처 검토와 후속 설계 합의를 기록한다. 2026-10-26에 라우팅 비교와 모델 품질 비교를 함께 다루고, 현재 동작을 보존하며, 실험별 규칙과 공통 실행 수명 사이에 seam을 두는 추천안을 확정했다. 설계 기록을 승인한 뒤 `implement` 요청으로 구현과 검증 후 현재 브랜치 커밋을 승인했다. 아래 설계 합의와 후속 구현·검증 결과는 구분한다.

## 근거와 목표

[현재 비교 실행기](../../tests/integration/routing-pilot-browser.mjs)의 `runPilot`은 실험 종류와 mock/live 실행을 여러 인자의 조합으로 표현한다. 같은 실행 흐름에서 corpus 검증, 브라우저 준비, 요청 가로채기, 비용 예약·정산, 원문 census, 결과 판정, 증거 저장과 정리를 수행하면서 실험별 분기가 반복된다.

이 module은 단순 전달자가 아니다. 삭제하면 실행 순서와 안전 규칙이 호출자에 흩어진다. 목표는 파일 크기 감소가 아니라 호출자가 알아야 하는 조합을 줄여 depth를 높이고, 실행 불변식의 locality와 두 실험의 leverage를 확보하는 것이다. 이 판단은 소스·호출 관계·기존 테스트를 읽은 정적 검토이며, 변경 비용이나 실행 성능의 측정 결과는 아니다.

## 합의한 책임과 interface

실험별 module은 다음 규칙을 소유한다.

- 라우팅 비교: 실험 계획, 라우팅 정책에 따른 요청 변환·검증, 결과 자격 판정과 요약.
- 모델 품질 비교: 프로필별 계획, 모델·reasoning·요청 계약, 독립 원문 census와 보호 내용에 따른 결과 자격 판정, 호환성 판정과 요약.

공통 실행 module은 브라우저 준비, 계획 실행, 요청 수명, 비용 예약·정산, 증거 저장, 중단과 정리를 소유한다. 실험 규칙은 실행의 각 단계에서 필요한 판단을 제공하고, 공통 실행 module은 그 판단을 적용하는 순서와 자원 수명을 책임진다. 독립 원문 census의 관찰 결과를 제품 serializer의 결과로 대체하지 않는다.

interface는 실험 규칙과 실행 adapter를 받아 한 번의 실행을 완료하거나 중단하고, 그 결과와 증거를 남기는 형태로 좁힌다. 네트워크 ID, 진행 중 작업, 실행 문맥과 정산 대기 상태는 implementation 내부에 둔다. mock/live의 전송 차이는 adapter로 표현하고, 기존 실행 전체에 흩어진 모드 조합 판별을 줄인다. 실험 종류와 합성 비용 여부 등 증거에 필요한 구분은 유지한다.

현재 내부 호출자는 함께 수정한다. 기존 내부 인자 조합을 위한 호환 module은 추가하지 않는다. CLI와 저장된 증거 형식은 아래 보존 계약을 따른다. 범용 실험 등록 체계는 이번 범위에 포함하지 않는다.

## 재사용과 보존 계약

[비용 장부](../../tests/integration/routing-budget.mjs)의 `reserve / settle / snapshot`, [브라우저 하네스](../../tests/integration/harness.mjs), [자격 증명을 보관하는 전송 adapter](../../tests/integration/live-key.mjs)를 재사용한다. 실제 키는 기존 Node 전송 콜백 안에 머물며, 브라우저에는 합성 키만 전달한다. 공통 실행 module의 새 테스트 seam에서도 이 자격 증명 수명을 바꾸지 않는다.

보존 대상은 다음과 같다.

- CLI 옵션, 종료 상태, 출력 의미와 증거 파일 형식.
- 동기화 폴더 밖의 새 출력 디렉터리, 디렉터리 0700·파일 0600, 기존 대상 덮어쓰기 거절.
- mock/live 구분, 합성 비용 표시, 실제 비용 불명과 의미적 품질 미판정의 표현.
- 고정 corpus, 독립 원문 census, 중복 원문 개수, 보호 내용과 실제 적용 여부의 검사.
- WMT 참조문과 모델 입력·블라인드 평가 자료의 분리.
- 요청 전 비용 예약과 예약 증거 저장, 공유 과금 한도, 비용 불명 시 예약 유지·장부 동결·후속 전송 차단.
- 호환성 검사와 본 비교 사이의 동일 장부 공유, 불완전 실행의 개별 증거, 완료 실행의 요약·블라인드 자료·매핑.
- 진행 중 요청의 처리와 정산 대기, 중단·정리 순서, 해당 실행이 만든 브라우저·연결·서버의 정리.
- 증거 저장 실패 시에도 수행되는 기존 정리와 전송 adapter 수명 종료.

제품의 Semantic Block, Inline Translation Session·Operation, Session Budget, Translation Chunk의 복구와 전체 결과 게시 규칙은 변경하지 않는다. 평가 비용 장부와 제품 Session Budget은 별개로 유지한다. 이 범위는 기존 ADR과 충돌하지 않는다.

## 검증 설계

테스트와 호출자는 같은 실행 interface를 사용한다. 결정적 실행 adapter는 외부 의존성만 대체하고, 실제 비용 장부와 실행 implementation을 통과한다. 테스트는 사적 상태보다 전송 인자·순서, 반환·실패 결과, 증거와 자원 정리를 관찰한다.

| 상황 | 관찰할 결과 |
| --- | --- |
| 정상 요청 | 예약과 예약 증거 저장 이후 전송하고, 응답을 정산한 뒤 다음 실행으로 진행한다. |
| 예약 또는 예약 증거 저장 실패 | 해당 요청을 전송하지 않고 기존 실패·정리 계약을 따른다. |
| 비용 불명 | 예약을 유지하고 장부를 동결하며 후속 전송을 차단한다. |
| 중단 또는 오류 | 진행 중 요청의 처리·정산 대기와 미정산 처리를 거쳐 가능한 증거를 보존한다. |
| 정상·실패·증거 저장 실패 | 해당 실행의 자원을 정리하고 전송 adapter 수명을 종료한다. |
| 실험별 결과 판정 | 기존 라우팅 자격 판정과 모델 품질 census·보호 내용·적용 완료 판정이 유지된다. |

기존 장부·요청 변환·결과 판정 검사를 유지하고, 실행 수명에서 빠진 검사를 기존 테스트 관례로 보완한다. 실행 interface로 대체되는 검사만 중복 여부를 판단하며, 별개의 계약을 검사하는 테스트는 유지한다. 새 안전 검사는 같은 절차와 환경에서 의도한 위반을 잡는 음성 대조군도 확인한다. 소스 변이는 공용 `mutation-probe.py` 절차를 따른다.

구현 후 읽기 전용 검토와 필요한 수정을 마친 다음 소스를 고정하고 `npm test`, `npm run check:syntax`, `npm run check:docs`를 실행한다. 두 실험의 비과금 브라우저 검사는 `test:integration:routing-pilot`과 `test:integration:model-quality`이며, 상세 선행 조건과 인자는 [테스트 안내](../../tests/README.md)를 따른다.

모델 품질 브라우저 검사는 기존 고정 WMT corpus를 사용한다. corpus가 없으면 임의로 재구성하지 않고 해당 검증을 미실행으로 보고한다. 실제 모델 과금 실행은 별도 승인 범위이며, 비과금 통과를 실제 제공자 호환성·모델 품질·과금 검증으로 표현하지 않는다.

## 확정 범위와 검토 기준

| 저장소 | 작업 범위 | 공개 테스트 seam | 검토 기준 |
| --- | --- | --- | --- |
| chrome-ai-translator | 비교 실행기, 라우팅·모델 품질 비교 진입점과 실험 규칙, 필요한 실행 module·adapter, 관련 테스트·문서 | 공통 실행 interface와 결정적 adapter의 전송·저장·정리 관찰, 기존 CLI·증거 파일, 두 실험의 비과금 브라우저 경로 | `5845180e971ad97b9a91cfe544c350e6e5aa47a8` 대비 최종 변경 전체 |

이 설계는 평가 도구의 책임 배치를 다룬다. 제품 도메인 용어의 추가·재정의가 없어 용어집은 변경하지 않는다. 되돌릴 수 있는 내부 책임 정리이므로 별도 ADR은 추가하지 않는다. 후속 `implement` 요청은 코드 구현, 합의한 비과금 검증·리뷰와 현재 브랜치 커밋을 포함한다. 실제 과금 실행과 푸시는 포함하지 않는다.
