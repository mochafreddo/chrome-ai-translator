# UI polish 접근성 지적의 수정 설계

이 문서는 기준 커밋 `920adcee638dea49828d230a841cc73bde336e51` 이후 UI polish 감사에서 확인한 두 접근성 지적과 설계 인터뷰의 합의 내용을 기록한다. 2026-10-26에 Q1부터 Q4까지의 추천안을 수락했고, 최종 범위·검증 기준을 제시한 뒤 같은 날 `implement` 요청으로 구현을 승인했다. 이 문서의 근거 절은 수정 전 감사 기록이며, 구현과 검증 결과는 별도로 보고한다.

## 확인한 근거

[사이드 패널 문서](../../extension/sidepanel.html)의 영어 선언이 원문과 번역문에도 상속된다. 실제 렌더러에 한국어 결과를 넣은 감사에서는 결과 자체의 언어 지정이 없고 상속 언어가 `en`인 것을 확인했다. 이는 합성 콘텐츠를 사용한 DOM 관측이며, 모델 번역이나 스크린리더 음성 출력을 검증한 결과는 아니다.

[사이드 패널 상태](../../extension/background.js)는 원문의 `langHint`와 번역 당시의 `settingsUsed`를 전달한다. [현재 언어 판별](../../extension/translation-settings.js)은 영어·한국어 표기를 인식하고 나머지는 빈 문자열을 반환한다. [이중언어 보기](../../extension/sidepanel.js)는 영어 구분 문구와 원문·번역문을 하나의 문자열로 합친다.

[진단 표시](../../extension/options.html)는 포커스 지정이 없는 `<pre>`이며, [스타일](../../extension/styles.css)이 최대 높이와 내부 스크롤을 적용한다. 감사의 긴 합성 진단 내용은 표시 높이 358 CSS px, 전체 스크롤 높이 2,233 CSS px였으며 포커스 가능한 자식이 없었다. 기존 CSS에서는 해당 내용이 내부 스크롤 없이 문서 흐름으로 표시됐다.

[manifest](../../extension/manifest.json)의 지원 하한은 Chrome 116이다. [Chrome 공식 설명](https://developer.chrome.com/blog/keyboard-focusable-scrollers)에 따르면 스크롤 영역의 자동 키보드 포커스는 Chrome 132부터 제공된다. 구버전 호환성 지적은 소스와 공식 문서에 근거하며, Chrome 116에서 직접 실행해 확인한 결과는 아니다.

## 합의한 결정

### Q1: 원문과 번역문의 언어 범위 구분

영어 UI 선언은 유지한다. 원문과 번역문에는 각각의 언어를 지정하고, 이중언어 보기에서도 원문·번역문·영어 구분 문구의 언어 범위를 분리한다. 화면 배치와 표시 문구는 유지한다. 로딩·빈 상태·오류 등 영어 UI 문구는 번역 결과의 언어 선언을 받지 않는다. 원문과 번역문은 계속 텍스트로 취급하며 HTML로 해석하지 않는다.

### Q2: 진단 영역의 높이 제한과 키보드 접근

진단 영역의 360 CSS px 높이 제한을 유지한다. 명시적인 키보드 포커스와 접근 가능한 이름을 제공하고, Tab으로 진입한 뒤 방향키와 Page Down으로 내용을 읽고 다시 빠져나올 수 있게 한다. Chrome 116 지원 하한을 유지한다.

### Q3: 확인할 수 없는 언어와 번역 당시 설정

기존 영어·한국어 판별과 검증된 표준 언어 코드를 사용한다. 언어를 확인할 수 없는 값에는 `lang=""`를 지정해 영어 상속을 끊고 언어 미지정을 명시한다. 언어 이름 사전이나 자동 감지를 추가하지 않는다. 예를 들어 표준 코드 `ja`는 사용할 수 있지만, 기존 판별기가 인식하지 않는 `Japanese`라는 이름을 새로 해석하는 사전은 추가하지 않는다.

원문에는 추출한 문서의 언어 힌트를 사용한다. 이는 페이지가 선언한 값이며 실제 본문의 언어를 독립적으로 검증했다는 뜻은 아니다. 번역문에는 해당 결과의 `settingsUsed.targetLanguage`를 사용한다. 현재 편집 중인 입력값이나 이후 저장한 기본 설정이 기존 결과의 언어 선언을 바꾸지 않는다. 필요한 언어 정보가 없거나 사용할 수 없으면 영어를 추정하지 않고 미지정 처리한다.

### Q4: 빈 상태와 내용 갱신의 포커스 정책

진단 내용이 비었거나 짧더라도 진단 영역을 하나의 탭 순서 지점으로 유지한다. 기존 제목을 접근 가능한 이름으로 사용하고 명시적인 포커스와 가시적인 포커스 표시를 제공한다. 내용 길이나 창 크기에 따라 탭 순서를 바꾸는 별도 로직은 추가하지 않는다.

내용이 갱신돼도 진단 영역이나 다른 컨트롤로 포커스를 강제로 옮기지 않는다. 스크롤과 Tab·Shift+Tab 이동에는 브라우저의 기본 동작을 사용하며 별도 키보드 처리기를 만들지 않는다.

| chrome-ai-translator | 사이드 패널의 콘텐츠 언어·이중언어 렌더링, 필요한 언어 표시 헬퍼와 로더, Options 진단 영역의 의미·포커스, 관련 단위·브라우저 검사, 이 설계 문서와 색인 | 실제 렌더러가 만든 DOM의 텍스트·언어 범위, 번역 당시 설정과 결과의 연결, 진단 영역의 접근 가능한 이름·탭 순서·실제 스크롤·포커스 유지 | `920adcee638dea49828d230a841cc73bde336e51` 대비 기존 UI polish와 이번 후속 수정을 포함한 작업 트리 |

단위 검사는 영어·한국어 별칭, 검증된 표준 코드, 미지정·잘못된 값, 번역 당시 설정과 현재 입력의 차이를 다룬다. 렌더링 검사는 번역만 보기와 이중언어 보기에서 원문·번역문·영어 구분 문구의 텍스트와 언어 범위를 확인하고, 일반 텍스트가 HTML로 해석되지 않는 기존 경계를 확인한다.

브라우저 검사는 빈 상태·짧은 내용·360 CSS px을 넘는 긴 진단 내용을 사용한다. Tab으로 진입해 이름과 포커스 표시를 확인하고, 긴 내용에서는 방향키·Page Down의 실제 스크롤을 확인한 뒤 Tab·Shift+Tab으로 빠져나온다. 내용 갱신 시 포커스를 강제로 이동시키지 않는지도 확인한다. 최근 Chrome의 자동 포커스만으로 통과하지 않도록 명시적인 포커스 계약도 확인한다.

후속 구현에서는 단위·구문·문서 검사와 영향을 받는 비과금 UI 검사를 실행하고, 두 지적을 되살린 대조군이 회귀 검사에서 실패하는지 확인한다. 언어 표시용 처리 때문에 기존 번역 품질 판별·요청·캐시·저장·권한 계약을 바꾸지 않는다. 검증에는 모델 호출이나 새 패키지 설치가 필요하지 않다.

현재 사용 가능한 Chrome에서의 실행과 Chrome 116 호환성에 대한 소스·공식 문서 근거는 구분해서 보고한다. Chrome 116 실행이나 스크린리더 음성 검증을 하지 못하면 수행한 것처럼 표현하지 않는다. 설계 확인은 구현 시작, 커밋, 푸시 또는 배포를 뜻하지 않는다.

## 문서화 경계

이번 결정은 일반적인 접근성 처리이며 새 번역 도메인 용어를 만들지 않는다. 용어집에는 구현 세부 사항을 추가하지 않는다. 현재 선택은 국소적이고 되돌리기 쉬우므로 새 ADR을 만들지 않는다. 후속 결정은 이 문서에 이어서 기록한다.
