# 검증 환경 개선

이 문서는 버튼 보존 구현과 푸시 이후의 회고에서 사용자가 수락한 네 가지 환경 개선을 기록한다. 작업 기준은 `6d9da2f2a5b2fa94156005d027ae46841250c6b6`이다.

## 승인한 범위

1. 버튼과 제목 링크 브라우저 검사를 로컬 fixture와 공개 페이지 모드로 분리하고 로컬 검사만 CI에 연결한다. 기본 실행은 기존의 두 단계 검사를 유지한다. 공개 페이지 실패를 생략하거나 로컬 통과로 대체하지 않는다.
2. 프로젝트 전용 로컬 검증 진입점에서 안전한 로그 권한과 명령 완료 증거를 자동으로 생성한다. 범용 명령 실행기나 별도 캐시는 추가하지 않는다.
3. 실제 키보드 입력에 기존 브라우저 드라이버를 사용하는 경로와 입력 후 페이지 반응을 기다리는 검증 예제를 테스트 가이드에 둔다.
4. 동일한 소스·도구·실행 조건과 성공 완료 기록을 확인할 때 로컬 검사 결과를 재사용한다. 공개 페이지·브라우저·유료 검사와 Git 대상 확인은 별도로 유지한다.

## 근거와 경계

이전 세션에서는 직접 구성한 CDP Enter 입력 검사가 실패했고 기존 브라우저 드라이버로 변경한 뒤 통과했다. 일부 증거 로그는 호출 명령에서 `umask`가 빠져 0644로 생성됐으며 별도의 owner-only 복사본이 필요했다. 커밋 이후 푸시 때 로컬 검사 묶음을 다시 실행했다. 이 사실은 반복과 잘못된 결과 해석을 줄이는 개선의 근거이며 절감 시간이나 개선율을 측정한 결과는 아니다.

기존 CI에는 단위·구문·문서·커밋 검사가 연결돼 있었다. 브라우저 fixture는 추가 작업으로 분리한다. 설치 버전을 고정하더라도 실제 Linux CI 통과는 작업 정의를 읽거나 macOS에서 브라우저 검사를 실행한 결과만으로 확정하지 않는다.

로컬 검증 기록은 기존 세 명령의 로그와 완료 상태를 소유한다. 재사용 판정은 기록과 현재 파일·체크아웃·도구·실행 조건을 비교한다. 소스가 검사 중 바뀌거나 완료 상태를 증명하지 못한 기록은 재사용하지 않는다. 비밀 파일이나 무관한 작업을 수집·수정해 기록을 맞추는 방식은 사용하지 않는다.

현재 사용법과 실행 범위는 [테스트 가이드](../../tests/README.md#local-verification-records), 입력 수집과 권한 검사의 구현은 [로컬 검증 진입점](../../scripts/verify-local.js)에 있다.
