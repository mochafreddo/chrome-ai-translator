# 성능 개선 설계 인터뷰

이 문서는 기준 커밋 `6e67502e4d8bad2312a8a98be1f1387aa5bf9af4`의 코드베이스 전체 성능 검토와 후속 설계 인터뷰를 기록한다. 2026-10-28에 사용자가 Q1부터 Q9까지의 추천안을 모두 수락하고 Q10의 최종 범위·공개 테스트 경계·검토 기준을 확정했다. 구현은 승인되지 않았다.

## 근거와 한계

## 합의한 방향

### Q1: 미전송 블록 기록 재사용

스크롤로 대기열에서 빠졌다가 다시 들어온 변경 없는 Semantic Block은 기존 기록을 재사용한다. 페이지가 바뀌었으면 다시 직렬화한다. 재시도, 진단, 복원에 필요한 기록은 보존한다. 동일 블록의 재등록 횟수에 비례해 기록이 계속 늘어나는 것을 제거하는 것이 목표다. 재사용 경계는 Q6에서 확정했다.

### Q2: 번역 대상과 타이밍을 보존하는 탐색 개선

이어지는 스캔은 중단한 탐색 위치에서 계속한다. 스크롤, 크기 변경, DOM 변경은 탐색을 무효화한다. 현재의 화면 주변 선행 탐색 범위, 250ms 대기, 숨김·편집 영역 제외, 적용 직전 안전 검사는 유지한다. 먼저 탐색 재개와 중복 조회를 개선한다. 번역 시작 시점이나 탐색 대상 변경은 추가하지 않는다. 탐색 도중 DOM 변경과 조회값의 재사용 수명은 Q7에서 확정했다.

### Q3: 폴링을 유지하는 본문 재전송 감소

초당 폴링과 Side Panel Translation 상태 응답 및 Inline Translation 상태 응답의 독립 처리를 유지한다. 진행률 갱신과 변경 없는 조회에서 큰 본문을 반복 전달하지 않는 방향을 채택한다. 탭 전환, 늦은 응답, 패널 재개방에서도 전체 상태를 복구할 수 있어야 한다. 이는 [기존 단순화 설계](codebase-simplification-2026-10-26.md)의 폴링 유지 결정을 계승한다.

현재 패널은 전체 상태 알림을 받으면 진행 중 상태 조회를 무효화하고 상태를 통째로 교체한다. 진행률만 담은 메시지를 그대로 넣거나 단순 병합하는 것으로는 최초 본문 조회와의 경쟁을 해결하지 못한다. 이를 다루는 복구 계약은 Q8에서 확정했다.

### Q4: 닫힌 탭의 보관 상태 정리

탭을 닫으면 해당 탭의 원문, 번역, 표시 상태를 해제한다. 진행 중 요청이 늦게 완료돼도 상태를 다시 만들지 못하게 한다. 이미 보낸 모델 요청의 취소·청구 정책 변경은 포함하지 않는다. 다른 탭의 결과와 요청을 보존한다.

### Q5: 지원 범위와 진단 계약 보존

진단 전체 읽기를 줄이더라도 Chrome 116 지원, 최근 20개 진단 보존, 구형·고아 기록 정리, 중복·충돌 판정, 저장 실패 시 기존 기록 보존을 유지한다. 이 조건을 깨거나 복잡한 캐시가 필요한 방안은 보류한다. [ADR-0009](../adr/0009-model-local-rejections-in-diagnostics-v3.md)의 저장 성공 후 퇴출 순서와 v2/v3 전역 보존·동일성 규칙은 유지한다.

보존할 ID를 고르는 데에는 두 인덱스가 필요하고, 동일성 판단에는 해당 run의 v2/v3 레코드가 필요하다. 고아·구형 기록 정리에는 인덱스에 없는 키 이름도 필요하다. 전체 읽기를 인덱스 조회만으로 바꾸면 이 정리 동작을 잃는다. 지원 API에 따른 읽기 경로는 Q9에서 확정했다.

플랫폼 확인 결과, [Chrome 공식 StorageArea 문서](https://developer.chrome.com/docs/extensions/reference/api/storage/StorageArea)는 `getKeys()`를 Chrome 130 이상으로 명시한다. `get(null)`은 저장소 전체를 반환한다. Context7의 해당 공식 문서 조회로 확인했다. 이 지원 범위를 전제로 Q9의 API 유무에 따른 분기를 채택했다.

### Q6: 재사용 가능한 미전송 기록의 경계

재사용 대상은 아직 요청하지 않은 일반 대기 블록이 대기열에서 해제된 기록으로 한정한다. 다시 들어올 때 원본 소유권을 확인하고, 그대로면 재사용한다. 바뀌었으면 다시 직렬화해 기록을 갱신한다. 이미 전송한 기록과 페이지 변경 재시도 기록은 별도로 보존한다. 진행 중 응답이 참조하는 기록을 다른 내용의 기록으로 재사용하지 않는다.

### Q7: 동기 탐색과 번역 적용 분리

한 차례의 동기 탐색에서 후보를 수집한 뒤 캐시 번역 등을 적용한다. 스타일·위치 조회값은 그 동기 탐색 안에서만 재사용한다. 캐시 적용을 포함해 DOM이 바뀌면 남은 탐색 위치를 무효화한다. 변경 가능한 페이지의 스타일·위치를 여러 스캔에 걸쳐 캐시하지 않는다.

### Q8: 본문 보유 여부를 확인하는 상태 복구

상태의 순서와 본문의 버전을 구분한다. 패널이 해당 본문을 실제로 보유한 경우에만 본문 전송을 생략한다. 본문이 없는데 진행 알림이 먼저 도착하면 즉시 본문을 요청한다. 새 번역, 탭 전환, 워커 재시작에서는 이전 본문 보유 정보를 무효화하고, 늦은 응답이 최신 상태를 덮지 못하게 한다. 워커 재시작으로 기존 번역 결과가 보존된다는 보장은 추가하지 않는다.

본문이 생략된 폴링 응답도 보유 중인 본문으로 렌더링해 보기 전환과 DOM 복구를 유지한다. Inline Translation 상태 응답은 계속 독립적으로 처리한다. 상태 응답·알림의 순서 판정과 본문 교체는 같은 Side Panel Translation 상태를 대상으로 일관돼야 한다.

### Q9: 지원 API에 따른 진단 저장 경로

`getKeys()`가 있으면 키 목록과 필요한 인덱스·레코드만 읽는다. 없는 Chrome 116~129에서는 현재 `get(null)`을 유지한다. 키 목록 캐시는 추가하지 않는다. API 실행 중 실패는 기존 진단 저장 실패로 처리하고 전체 읽기로 재시도하지 않는다. 저장 성공 후 삭제와 인덱스 밖 고아·구형 기록 정리는 양쪽 경로에서 동일하게 유지한다. 이번 개선 대상은 배치 진단 저장 경로이며 Options 조회·내보내기의 별도 읽기 최적화는 추가하지 않는다.

## Q10: 확정한 범위와 검증 기준

사용자는 다음 작업 범위와 검증 계획을 최종 설계로 수락했다. 구현은 별도 요청 후 진행한다.

| 저장소 | 작업 범위 | 공개 테스트 경계 | 검토 기준 |
| --- | --- | --- | --- |
| chrome-ai-translator | Q1~Q9의 다섯 성능 개선, 관련 기존 테스트·fixture 보완, 필요한 브라우저 검사 보완, 이 설계 문서·색인·테스트 안내 갱신 | Session·Viewport API, worker 메시지·탭 종료 이벤트, 실제 패널의 상태 복구·렌더링, 진단 저장소 API 인자·반환값과 보존 결과, 외부 HTTP 요청을 가로채는 비과금 브라우저 경로 | `6e67502e4d8bad2312a8a98be1f1387aa5bf9af4` 대비 설계 기록과 후속 구현을 포함한 작업 트리 |

검증 기준은 다음과 같다.

- 기록 재사용: 변경 없는 미전송 블록의 반복 해제·재등록에서 ID·직렬화 횟수·진행 집계를 확인한다. 원본 변경 시 새 내용으로 갱신하고, 이미 전송한 기록·페이지 변경 재시도·정확한 복원을 보존한다.
- 탐색: 1,200개 텍스트 노드를 넘는 DOM과 중첩 스크롤에서 재개·무효화·숨김 제외를 확인한다. 캐시 적용이 DOM을 바꿔도 누락·중복 번역이 없고, Stop 이후 예정된 콜백이 작업하지 않아야 한다. 동일 입력의 조회 횟수 감소를 확인하며 실행 시간 임계값을 단위 검사로 고정하지 않는다.
- 패널: 본문보다 먼저 온 진행 알림, 역순 응답, A→B→A, 새 번역, 패널 재개방과 워커 상태 초기화를 확인한다. 변경 없는 조회·진행 알림의 본문 전달량 감소와 원문·번역 언어, 보기 전환, DOM 복구, 독립 Inline 응답 처리를 확인한다.
- 탭 종료: 완료 후 종료, 번역 준비·진행 중 종료, 늦은 성공·실패 뒤 상태 미생성, 다른 탭 결과 보존을 공개 이벤트·메시지로 확인한다. 실제 힙 누수 해소를 문자열 전달량이나 Map 상태만으로 입증했다고 주장하지 않는다.
- 진단: `getKeys()` 유무, 관련 없는 큰 값의 미조회, 인덱스 밖 동일 run의 v2/v3 충돌, 고아·구형 기록 정리, 저장·삭제·키 열거 실패를 확인한다. fake 저장소도 요청한 키만 반환하도록 하여 읽기 범위를 실제 인자로 검증한다.

후속 구현에서 필요한 검토·수정을 마친 뒤 소스를 고정하고 `npm test`, `npm run check:syntax`, `npm run check:docs`를 실행한다. 브라우저 검사는 실제 패널 DOM·언어·보기 보존을 위한 `npm run test:integration:ui`, 가로챈 요청을 통한 실제 worker·페이지·패널 흐름의 `npm run test:integration:openrouter-inline`과 `npm run test:integration:openrouter-sidepanel`을 사용한다. 필요 동작이 기존 검사에 없으면 그 경로의 검사·fixture를 보완한다. 긴 DOM의 작업량과 전달량은 동일 fixture·뷰포트·브라우저 조건에서 수정 전후를 비교한다. 이것을 실제 모델 응답 지연 개선으로 해석하지 않는다.

각 회귀 검사는 수정 전 코드에서 실패하는 대조군을 먼저 확인한다. 소스 변이를 사용하는 경우 기존 `mutation-probe.py` 절차를 적용한다. 실제 API 키와 과금 모델 호출은 필요하지 않으며 `verify:live*`는 실행하지 않는다. 커밋·푸시·배포는 범위에 포함하지 않는다.

## 문서와 승인 경계

합의한 결정과 측정·추정의 경계는 이 설계 기록에 남긴다. 새 도메인 개념이 확정되지 않았으므로 용어집을 변경하지 않는다. ADR은 되돌리기 어렵고 맥락 없이는 의외이며 실제 절충이 있었던 결정에만 추가한다. 현재 아키텍처 문서를 미구현 설계로 바꾸지 않는다.

최종 설계 확인에는 이 저장소의 작업 범위, 공개 테스트 경계와 검토 기준을 한 질문에 포함했다. 구현, 커밋, 푸시와 배포는 이번 설계 확정에 포함되지 않는다.

Chrome 비교는 [성능 검사](../../tests/integration/performance.test.mjs)를 기준 코드와 구현 코드의 `extension/`에 각각 실행한다. 문단이 겹친 배치는 모든 문단을 같은 화면 주변 탐색 범위에 두기 위한 합성 조건이다. 작업량 측정에는 기록만 수집하는 Session 어댑터를 사용하고, 별도 실제 Session 사례에서 캐시 번역 1,300개, 새 요청 0개와 정확한 노드 복원을 확인한다. 진단 비교는 양쪽 저장 결과가 같은지 함께 검사하며, `getKeys()`가 없을 때의 전체 읽기 비용은 그대로다.

이 결과는 실제 사용자의 스크롤 지연, 화면 그리기 시간, 힙 사용량 또는 모델 응답 시간의 개선을 측정하지 않는다. 브라우저 번역 검사는 합성 키와 가로챈 HTTP 응답을 사용하며 번역 품질이나 실제 provider 호환성을 입증하지 않는다.

필수 `test:integration:ui`의 native ArrowDown 진단 영역 스크롤 검사는 Chrome 149.0.7827.115에서 실패했다. 수정 전 기준 코드 `6e67502`에서도 같은 실패를 확인했다. DOM 포커스와 신뢰된 키 이벤트는 관측했지만 네이티브 스크롤은 관측하지 못했다. 문서 활성화, 이벤트 형식, 프레임 대기, macOS 키 코드와 headed 실행을 구분해도 실패했으며 원인은 확정하지 않았다. 본문 생략·언어·보기·외부 DOM 복구 검사의 통과와 이 미통과 조건은 별개다. 해당 UI 완료 기준은 열린 상태로 남는다.
