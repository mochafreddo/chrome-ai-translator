# 텍스트 번역 페이지 설계 인터뷰

이 문서는 텍스트를 붙여넣어 번역하는 페이지와 기존 Side Panel Translation 제거에 관한 설계 인터뷰를 기록한다. 조사 기준은 `e5eda56a28f86f64cfe8a2fbe41a7409e55f4885`이다. 사용자의 후속 to-spec 요청으로 [명세 이슈 #112](https://github.com/mochafreddo/chrome-ai-translator/issues/112)를 게시했다. 제품 구현과 커밋·푸시·배포는 포함하지 않는다.

## 확인한 현재 구조

`extension/sidepanel.html`의 Translate current tab은 추출한 기사 Markdown을 번역하는 Side Panel Translation 진입점이다. Translate visible text는 별도의 Inline Translation 진입점이다. 현재 화면에 붙여넣기 입력란은 없다. 코드와 문서의 정적 확인이며 브라우저 실행이나 실제 모델 검증 결과는 아니다.

## 확정한 결정

사용자는 Q1–Q3에 “모두 추천안”으로 답해 다음 범위를 수락했다.

- Q1: 확장 프로그램 전용 독립 탭에 번역 페이지를 둔다. 북마크할 수 있으며 사이드 패널에 진입 버튼을 둔다. 기존 API 키와 번역 서비스 설정을 사용하고, 넓은 화면에서 원문과 번역문을 나란히 보여 준다.
- Q2: 첫 범위는 붙여넣기 텍스트 번역이다. 원문 자동 언어 판별, 대상 언어 선택, 원문·번역문 비교와 결과 복사를 포함한다. 파일·이미지·음성·웹사이트 주소 번역은 제외한다.
- Q3: Translate current tab의 버튼과 전용 기사 추출·번역 실행·결과 표시 및 관련 설정을 제거한다. 새 Text Translation에 필요한 공통 코드는 재사용한다. Inline Translation의 제어·진행 상태·중지·원문 복원과 새 페이지 진입점은 사이드 패널에 남긴다.

사용자는 Q4–Q7에도 “모두 추천안”으로 답해 다음 사용 방식을 수락했다.

- Q4: 붙여넣기나 입력만으로는 요청하지 않는다. 번역 버튼 또는 `Cmd/Ctrl+Enter`로 번역을 시작한다.
- Q5: 입력과 결과는 줄바꿈·문단 구분을 유지하는 일반 텍스트다. Markdown을 붙여넣어도 서식 화면으로 렌더링하지 않으며 결과도 일반 텍스트로 복사한다.
- Q6: 입력과 결과는 해당 번역 탭을 닫을 때까지 보관한다. 다른 탭으로 이동하거나 번역 페이지를 새로고침해도 복구하며 탭을 닫으면 지운다. 장기 번역 이력은 만들지 않고 모두 지우기 동작을 제공한다. 실행 중 새로고침의 종료 정책은 Q9를 따른다.
- Q7: 기존 기본 설정으로 시작하되 페이지에서 대상 언어·말투·서비스·모델을 바꿀 수 있다. 변경은 해당 페이지에만 적용하며 기본값으로 저장할 때만 인라인 번역에도 사용하는 기본 설정을 변경한다. 기존 서비스별 모델 선택 정책을 따른다.

사용자는 Q8–Q10에도 “모두 추천안”으로 답해 다음 실행 경계를 수락했다.

- Q8: 한 번에 최대 60,000자를 받고 긴 글은 문단 경계를 우선해 자동 분할한 뒤 순서대로 번역한다. 분할 크기는 사용자 설정으로 제공하지 않는다. 제한을 넘으면 입력을 자르지 않고 번역 전에 안내한다.
- Q9: 번역 중 원문·언어·서비스·모델 변경과 중복 실행을 막고 중지를 제공한다. 중지·모두 지우기·새로고침·탭 닫기는 진행 중 작업을 종료하며 늦은 응답이 화면을 덮어쓰지 못하게 한다. 새로고침 후 자동 재실행하지 않는다. 이미 전송된 요청은 중지 후에도 과금될 수 있다.
- Q10: 원문 언어는 자동 감지를 기본으로 하며 직접 선택도 지원한다. 자동 감지를 위한 별도 모델 호출은 하지 않고 번역 요청에서 원문 언어를 판단한다.

사용자는 Q11–Q13에도 “모두 추천안”으로 답해 다음 결과 처리 방식을 수락했다.

- Q11: 분할한 글의 번역이 하나씩 완료될 때마다 결과를 표시한다. 중지·실패 시 완료된 결과를 보존하고 미완료임을 표시한다. 원문과 설정이 같으면 이어서 번역으로 남은 부분부터 진행한다. 자동 재시도는 하지 않는다.
- Q12: 완료된 번역문을 새 원문으로 옮기고 원문·대상 언어를 맞바꾸는 버튼을 둔다. 자동 감지 결과에서 원문 언어를 확정할 수 없으면 언어 선택을 안내한다. 맞바꾸기는 번역 요청을 보내지 않는다.
- Q13: 원문·설정을 수정해도 이전 결과를 남기고 이전 입력의 번역임을 표시한다. 새 번역을 시작하면 이전 결과를 비우고 새 결과를 표시한다. 원문·설정이 달라지면 기존 작업의 이어서 번역을 제공하지 않는다.

## 용어와 기존 결정

직접 입력한 텍스트의 번역은 Text Translation으로 구분하며 정의는 루트 용어집에 둔다. Side Panel Translation은 제거 대상인 현재 기능의 이름으로 유지한다. 구현 전에 현재 동작을 이미 제거된 것으로 설명하지 않는다.

ADR-0001의 도구 모음에서 사이드 패널을 여는 정책과 ADR-0004의 Inline Translation 단축키는 유지한다. 기존 Side Panel Translation의 청크 복구·완료 결과 및 문서 수명에 관한 결정은 새 Text Translation에 자동 적용하지 않는다. 새 기능의 완료 결과 보존과 명시적 이어서 번역은 [ADR-0015](../adr/0015-preserve-completed-text-translation-on-interruption.md)에 기록한다. ADR-0005·0006은 기존 기사 번역의 기록이며 제거 구현 시 현재 적용 상태를 정리한다. ADR-0014 중 인라인 문서 경계와 공급자 선택 보장은 유지한다.

## Q14: 최종 설계 확인안

사용 방식에 관한 Q1–Q13은 합의했다. 아래 최종 확인안을 제시한 뒤 사용자는 추가 답변 대신 to-spec을 요청했다. 추가 인터뷰 없이 이 범위를 명세에 구체화해 게시했으며, 이를 구현 승인이나 실행 검증 완료로 해석하지 않는다.

- 저장소는 `/Users/mochafreddo/GitHub/chrome-ai-translator`이며 검토 기준은 조사 기준인 `e5eda56a28f86f64cfe8a2fbe41a7409e55f4885`이다. 이후 구현에서 이 기준 이후의 동시 변경을 확인하고 보존한다.
- 작업 범위는 Q1–Q13의 Text Translation 페이지, 사이드 패널 진입점, 기사 Side Panel Translation 전용 UI·메시지·실행·설정·검사 제거 및 관련 문서 갱신이다. 현재 기능 전용 검사는 새 기능 검사로 대체하거나 제거 사유를 기록한다. 인라인 번역, 도구 모음과 기존 인라인 단축키, 서비스별 전송·키 관리·설정 저장 정책은 유지한다.
- 공개 테스트 접점은 페이지의 입력·버튼·키보드 조작·복사·복구 동작, 페이지와 워커 사이 메시지 경계, 번역 실행의 입력·진행 결과·중지·재개 경계 및 기존 설정 저장 인터페이스다. 비공개 내부 자료구조나 문구 일치를 계약으로 고정하지 않는다.
- 결정적 검사는 입력 길이와 문단 분할·순서, 일반 텍스트의 안전한 표시, 공급자와 설정 스냅샷, 실패·중지 후 완료 부분 보존, 동일 입력·설정만의 재개, 수정 후 이전 결과 표시, 늦은 응답 무효화, 새로고침·탭 종료·여러 번역 탭 사이의 수명 분리, 맞바꾸기와 명시적 실행을 확인한다. 재개 후에도 완료 부분을 다시 요청하지 않는지 모델 전송 경계의 인수로 확인한다.
- 최종 로컬 검증은 기존 `npm run verify:local` 절차를 사용한다. 새 페이지는 기존 harness를 재사용하는 전용 무료 브라우저 검사로 입력부터 결과 표시·복사·복구까지 확인한다. 고정 응답으로 실패·지연 응답을 재현하며 실제 모델 품질과 구분한다. 기존 도구 모음·관련 UI·인라인 번역 무료 회귀 검사를 함께 선택하고, 핵심 회귀 검사의 음성 대조를 남긴다.
- 실제 모델 호출과 품질 평가는 이번 설계의 기본 검증 범위에 포함하지 않는다. 별도 실검증 전까지 실제 공급자 호환성과 번역 품질은 미검증으로 남긴다. 구현·커밋·푸시·이슈 게시·배포는 별도 요청 범위다.

## 명세 게시 결과

명세 이슈 #112는 ready-for-agent 라벨과 열린 상태로 생성했다. 게시 도구의 created_verified 결과로 제목·본문의 정확한 일치와 라벨·상태를 원격에서 다시 확인했다. 이 결과는 게시 검증이며 구현이나 수락 기준 충족을 뜻하지 않는다.
